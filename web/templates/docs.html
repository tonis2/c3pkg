API & publishing from the command line

Everything the website does is available over a JSON API, so you can publish from scripts and CI.

Install with c3c fetch

c3pkg is a c3c fetch registry. Give --fetch-url the address of this site (without a trailing slash) and name a library as <author>/<package>, where the author is the owner's username shown on the package page. A version is optional and defaults to the latest.

{{hl "bash" (printf `c3c --fetch-url %s fetch alice/vk # latest, unpacked into vk.c3l/ c3c --fetch-url %s fetch alice/vk@1.0.0 # an exact version c3c --fetch-url %s fetch-list # every library c3c --fetch-url %s fetch-list vk # search by id (or tag:gpu) c3c --fetch-url %s fetch-info alice/vk # versions, checksums and sizes` .Base .Base .Base .Base .Base)}}

Behind it are three plain GETs: /index.json, /info/<author>/<package> and /download/<author>/<package>@<version> (without a version it serves the latest). Yanked versions are not offered as the latest but can still be fetched by exact version. The checksum in the info record is the sha256_file described below.

Authentication

Create a token under Settings → API tokens and send it as a bearer token. Tokens are shown once; keep them secret and revoke any you lose.

{{hl "bash" (printf `export C3PKG_TOKEN=c3p_… curl -H "Authorization: Bearer $C3PKG_TOKEN" %s/api/v1/me` .Base)}}

Errors are JSON: {"error": "…", "errors": {"field": "message"}}. Requests are rate limited; on 429 wait for the Retry-After seconds.

Publish a library

A .c3l is a zip with manifest.json at its root. The package name is the manifest's provides, and it must match the name in the URL. Versions are semver (1.2.3 or 1.2.3-rc.1) and can never be changed once published.

{{hl "bash" (printf `# new package: description is required the first time curl -X PUT -H "Authorization: Bearer $C3PKG_TOKEN" \ -F file=@vk.c3l -F c3_version=0.7.5 \ -F description="Vulkan bindings for C3" -F tags="gpu,vulkan" -F license=MIT \ %s/api/v1/packages/vk/versions/1.0.0 # a new version of a package you own curl -X PUT -H "Authorization: Bearer $C3PKG_TOKEN" \ -F file=@vk.c3l -F c3_version=0.7.5 \ %s/api/v1/packages/vk/versions/1.0.1` .Base .Base)}}

Optional form fields for a new package: license, docs_url, git_url and a readme file. Without one, the README.md at the root of the .c3l becomes the README; publishing a new version refreshes it from the archive unless you uploaded a README yourself. Success returns 201 with {"name", "version", "created", "url"}.

Package index (for build tools)

Plain, cache-friendly endpoints a package manager can use to resolve and fetch versions, in the style of the Go module proxy.

GET /index/{name}/listOne version per line, newest first, yanked versions left out
GET /index/{name}/{version}.jsonC3 version, platforms, size, checksums, yanked flag
GET /index/{name}/{version}.c3lThe library file

Yanked versions are not listed but can still be fetched by exact version, so existing builds keep working.

Checksums

Each version has two SHA-256 values. sha256_file is the hash of the uploaded .c3l. sha256_tree hashes the contents, ignoring zip metadata, so a zipped library and its unpacked directory give the same value:

{{hl "bash" `cd unpacked-library find . -type f | sed 's|^\./||' | LC_ALL=C sort \ | while read f; do echo "$(sha256sum "$f" | cut -c1-64) $f"; done \ | sha256sum`}}
{{end}}
